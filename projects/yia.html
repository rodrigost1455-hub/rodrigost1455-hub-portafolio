YIA — a RAG assistant that cites its source or says it doesn't know.

It searches quality documents first (work instructions, control plans, complaints, lessons learned) and only then writes the answer, citing where it came from.

prototypeproof of conceptIT review in progress

problem

The answer to most quality questions already exists in a work instruction, a control plan, a past complaint or a lessons-learned entry. Finding it is slow, and a chatbot that answers from general knowledge is dangerous in a plant: an invented value looks exactly like a real one.

solution

YIA retrieves first and writes second. Documents are read and split into chunks, turned into embeddings, and searched by similarity. The top 8 fragments go to the model, which may answer only from those fragments and must cite the source. If nothing relevant is found, it says so.

It is plain Python + Streamlit + NumPy, with no third-party AI frameworks, in about 2,900 lines.

evaluation

I built my own test set instead of judging it by eye.

CheckResult

Limits. It sometimes adds detail that the document does not actually say, and it does not read images. The evaluation is self-run and small.

status

Honest status. A prototype (proof of concept) running in the cloud on de-identified documents, in review with IT. It is not a production product.

what I learned

  • Rejecting out-of-scope questions is a feature that needs its own tests, not a side effect.
  • Restricting the model to retrieved fragments turns "is it right?" into "does the cited source say it?".
  • Publishing the known failure modes next to the score makes the score credible.
