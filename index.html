Axionix POS — a multi-tenant point-of-sale that serves two real businesses today.

context

Two SMBs in Durango — a barbershop (Bigote Rojo) and a truck-parts retailer (Tracto Partes La Curva) — were running daily ops out of WhatsApp and pen-and-paper. Each needed inventory, sales, and reports. Building one POS each would mean two codebases to maintain.

decision

Bet on a multi-tenant FastAPI core behind one PostgreSQL with row-level tenant isolation, RBAC, and a single Next.js admin shell. One codebase, two live tenants — and a clean path to SaaS billing without re-platforming.

impact

2 live tenants running real transactions today · multi-branch ready for horizontal scale · roadmap to Stripe/Conekta SaaS billing (Fase 5) without infra rewrite.

2tenants live
Real revenue, real bugs, real customers. Not a hackathon demo. Schema, billing model, and RBAC designed for tenant #3 onward.

QIR & 8D — replaced an Excel-and-email quality workflow at a Tier 1 automotive plant.

context

Yazaki Planta P84 was running their Quality Issue Reports (QIR) and 8D problem-solving through emailed Excel files. SLAs got lost in inboxes; reports lived in seventeen versions; auditors hated it; IATF 16949 governance demanded traceability nobody could prove.

decision

Build a structured wizard over a FastAPI + Postgres core, with a server-rendered admin panel, SLA-aware status banners, auto-escalation to admins on breach, and PDF reports generated server-side via xhtml2pdf — so the artifact auditors hold is identical to the database row.

impact

Replaced the Excel + email chain with a single source of truth · SLA breach auto-escalation to admins · Alembic-tracked migrations on Railway Postgres · audit trail per QIR since day one.

8Dstructured
Eight-Discipline problem-solving encoded in code — every step gated, timestamped, owned. No more "who has the latest version?"

// case study · sole engineer · 2025

Watson ML Classifier — 100% precision on phantom-current sensor defects.

context

PHEV current sensors from Littelfuse were showing intermittent BEC defects on End-of-Line testers — and the supplier was pushing back on the data, calling them phantom readings. We needed a defensible classifier built on the actual EOL tester output, not on supplier reports.

decision

Skip notebook-only experiments. Build a real pipeline: a custom parser that extracts 34 features from raw EOL TXT files, AutoAI-driven model selection landing on a cross-validated Decision Tree, deployed to IBM Watson ML, and consumed by a Next.js front-end through a secure server-side API route (so the IBM key never reaches the browser).

impact

100% precision on holdout · supplier dispute resolved with auditable evidence · live web app for plant engineers to score new sensors on demand.

34features
From raw TXT to deployed endpoint — feature engineering, training, AutoAI selection, deploy. The pipeline is the product.

[next.js] /api/predict → server-side IBM_API_KEY · no leak to client
[result] ✓ supplier (littelfuse) concedes · data-driven win.
